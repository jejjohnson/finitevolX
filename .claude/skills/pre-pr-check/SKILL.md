# Pre-PR check

Run from the repo root and fix what fails before committing. Report results
honestly: what ran, what passed, what was skipped and why.

## Always

```bash
uv run ruff check .                 # entire repo: tests/ and scripts/ too (docs/ is excluded)
uv run ruff format --check .
uv run ty check finitevolx          # what CI's lint and typecheck workflows run
uv run pytest tests -n auto         # every test; CI runs `uv run pytest tests -v`
```

`make uv-lint` runs the first three; `make ci` runs all four (serially,
which is slow: prefer `-n auto` for the tests). There are no `slow` /
`integration` markers, so nothing is skipped by default; CI runs the suite
on Ubuntu and macOS with Python 3.12 and 3.13.

## When an operator's output changed

- On purpose: `uv run python tests/fixtures/_gen_golden.py`, then
  `git diff --stat tests/fixtures/golden/` must list exactly the operators
  you meant to change; explain the change in the PR.
- Not on purpose: a failing `tests/test_*_masks.py` is a regression — fix
  the code, never regenerate to make it pass.
- `tests/test_scale_covariance.py` and `tests/test_convergence.py` must still
  pass; an `xfail` that starts passing fails the run (`xfail_strict`): drop
  the marker if the fix is real.

## When the public API changed

```bash
make capabilities
uv run pytest tests/test_capabilities.py
```

…plus the `::: finitevolx.Name` entry on its `docs/api/*.md` page and the
name in `finitevolx.__all__`, in its logical group.

## When dependencies changed

`uv lock` and commit `uv.lock`; for spectraldiffx / gaussx, the
`bump-upstream-pins` skill.

## When docs or docstrings changed

```bash
uv run mkdocs build 2>&1 | grep WARNING
```

Compare with the same command on `main`: the existing docstrings raise
about 115 griffe warnings, so `--strict` does not pass yet, but your change
must add none. If `pandoc` is installed locally, take it off `PATH` first
(mkdocs-jupyter's jupytext probe can hang on the API pages).

No workflow builds the docs on a pull request (`pages.yml` deploys from
`main`), so a broken page is only caught here. Doctests are not collected:
run any new `Examples` snippet by hand. Notebook figures are regenerated by
running the notebook script (`add-notebook` skill).

## Before pushing

- `git status` shows no stray files (Zarr stores or GIFs a script wrote
  outside the ignored `outputs/`, PNGs a notebook rewrote that you did not
  mean to change, an unintended `uv.lock` change).
- Conventional Commits title with a lowercase subject; `!` and a
  `BREAKING CHANGE:` footer for a breaking change.
- Push only to your feature branch, only when asked.
